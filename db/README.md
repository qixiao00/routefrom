# 数据库

`db/migrations` 中的迁移文件定义 RouteFrom 的 Postgres/PostGIS 数据模型。应使用数据库直连地址，严格按照文件名顺序执行 `0001`—`0011`；连接池地址只供应用查询使用，不执行 DDL。

数据模型有意将以下内容分开保存：

- 不可修改的上传数据集；
- 不可变的导入批次和标准化 GPS 定位点；
- 候选、激活和已替代的处理运行与逐阶段算法版本；
- 点质量、连续边、观测缺口、运动状态、停留、地点、行程和交通方式概率；
- 清洗、平滑、地图匹配三类轨迹表示，以及日历无关的顶点和块；
- 任意多个 UTC 左闭右开时间区间；
- 不可变的完整地图配置修订和通用生成资产。

`0008`、`0009` 和 `0011` 在替换初始骨架表前会将旧表重命名为 `legacy_*`，不会静默删除旧结果。新派生表都携带 `processing_run_id`；只有 `app.activate_processing_run(uuid)` 能在导入及所有阶段成功后原子激活候选版本。

开发环境可通过 `processor[dev]` 中的 `pglast` 解析所有迁移；`processor/tests/test_database_migrations.py` 同时检查迁移连续性、版本边界、推测距离隔离和多区间契约。正式部署仍必须在与生产相同主版本的临时 Postgres/PostGIS 数据库中完整执行一次迁移。

原始 CSV 文件以及生成的二进制或 JSON 资产不直接存入 Postgres。数据库只记录这些私有文件在本地存储或对象存储中的键值和相关元数据。

身份认证方式确定后，再添加认证集成和行级安全策略（RLS）。在此之前，数据库只能由服务端访问，不能将数据库连接信息暴露给浏览器前端。
