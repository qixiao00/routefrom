# RouteFrom 前端体验架构

状态：探索性体验草案，尚未得到用户确认，不是视觉、页面或接口定稿。它只记录可供后续共同评审的方向；已确认内容仅限 `app/` 中的技术栈与工作台布局骨架。探索性视觉令牌见 `app/design/routefrom.design-dna.json`，算法语义见 `docs/FOOTPRINT_PROCESSING_ALGORITHM.md`。

## 1. 产品定位

RouteFrom 是一个个人时空观测台，不是定位数据后台，也不是旅行统计看板。

核心用户是希望回看、理解并修正自己长期足迹的人。核心页面只有一个任务：在地图和时间之间建立可信、可解释的个人记忆。

产品始终区分四类认识状态：

- **确认观测**：真实点、轨迹、访问和交通分段；
- **可疑观测**：数据仍保留，但置信度较低；
- **未知时间**：手机未带、关机或没有采样；
- **推测连接**：只为理解上下文生成的虚线路线或开放边界猜测。

界面不能把未知伪装成精确，也不能把算法结论伪装成用户亲自确认的事实。

## 2. 设计方向

### 2.1 令牌摘要

- 主色 `#63E6C5`：确认轨迹、当前时间和焦点；
- 停留色 `#D9A657`：访问和地点；
- 信息色 `#72A7FF`：第二时间切片、开放边界和对比；
- 未知色 `#77827E`：断点和无观测范围；
- 排除色 `#FF6B6E`：被排除点和明确处理错误；
- 背景 `#080B0E`，面板 `#10151A`，浮层 `#171D22`；
- 标题使用 IBM Plex Sans Condensed 风格，正文使用 IBM Plex Sans/思源黑体风格，坐标和时间使用 IBM Plex Mono；
- 4px 基础间距，6/10/14px 圆角，1px 矿物灰结构线；
- 动效 110/220/420ms，统一 `cubic-bezier(0.22, 1, 0.36, 1)`。

### 2.2 视觉签名：时间地层

时间轴不再是普通横条图，而是一条可缩放的“时间地层”：

- 移动、停留、可能停下、交通方式和质量状态是不同层；
- 未知时间表现为地层断裂，不使用实色区段；
- 推测连接使用明确虚线；
- 多个时间切片像覆盖在地层上的透明取样窗；
- 地图上的轨迹、检查器中的证据和地层共享同一选择状态。

这是 RouteFrom 唯一刻意强化的视觉元素。其他区域保持安静，避免“每块都发光”的 AI 风格。

### 2.3 从初始方案到最终方案的自检

初始骨架的优点是地图中心、密度克制和整体沉浸；问题是容易变成通用的“深色 SaaS + 薄荷绿 + 四栏仪表盘”：

- 工具栏按技术对象分成图层、数据、地图、样式；
- 所有信息被做成相似卡片；
- 时间轴只是装饰性条带；
- 地图和右侧检查器都展示固定演示内容；
- 颜色只能表示开关，没有表达真实性与未知性。

修订决定：

1. 导航按用户任务而非实现模块命名；
2. 卡片只用于“一个可选择的语义对象”或“证据集合”，普通设置回归列表；
3. 时间地层提升为主编辑器，与地图共同占据视觉主位；
4. 右侧检查器由选择驱动，并允许在紧凑桌面中浮出；
5. 所有算法状态都有颜色之外的形状、线型和文字冗余编码。

## 3. 产品信息架构

### 3.1 一级工作区

工具轨道不再使用“图层/数据/地图/样式”，改为：

1. **探索**：地图、时间地层、图层和命名时间选择；
2. **时间线**：按访问—行程—访问组织的事件流；
3. **地点**：地点库、层级边界和历史访问；
4. **质量审阅**：异常点、观测缺口、低置信事件和人工修正；
5. **处理版本**：导入、候选处理、差异审查、发布和回滚。

“底图样式”“图层参数”等技术设置属于探索内的局部控制，不占一级导航。

### 3.2 全局对象

顶栏包含：

- RouteFrom 与当前数据集；
- 当前保存视图；
- 时间选择摘要，例如“4 个区间 · 共 11 天”，而不是假装只有开始和结束；
- 全局搜索/命令入口；
- 当前处理版本状态；
- 帮助和账户。

### 3.3 左侧上下文坞

左侧内容由一级工作区决定：

- 探索：可视图层、时间选择、显示偏好；
- 时间线：事件类型、置信度、交通方式过滤；
- 地点：地点搜索、分类、层级；
- 质量审阅：问题队列和处理状态；
- 处理版本：阶段、指标、候选差异。

### 3.4 右侧检查器

检查器支持六种实体：

- 点：原始值、标准化值、质量分数和前后边；
- 缺口：未知时间、两侧状态、可能连接和统计排除说明；
- 访问：确认/可能范围、地点、语义概率和边界；
- 行程：开放状态、确认距离、缺口和交通分段；
- 交通分段：层级方式概率和特征贡献；
- 地点：边界来源、层级、访问历史和人工锁。

检查器先显示用户能理解的事实，再展开“算法依据”。数据库字段名不直接暴露。

## 4. 桌面布局

### 4.1 宽桌面（≥1440px）

```text
┌──────────────────────────────── 顶栏 56 ────────────────────────────────┐
├─48─┬──── 左坞 288 ────┬──────────── 地图 / 空间场 ────────────┬─检查器 320─┤
│工具│ 图层 / 时间选择   │                                          │ 选中实体   │
│轨道│                  │                                          │ 事实 / 依据 │
├────┴──────────────────┴──────────────────────────────────────────┴──────────┤
│                 可折叠时间地层 56 / 220 / 360                            │
└────────────────────────────────────────────────────────────────────────────┘
```

左坞、检查器和时间地层均可调整大小。调整手柄支持鼠标、触控板和键盘。

### 4.2 普通桌面（1180–1439px）

```text
┌──────────────────────────── 顶栏 ────────────────────────────┐
├─48─┬── 左坞 260 ──┬──────────────── 地图 ───────────────────┤
│工具│              │                         [检查器召回按钮] │
│轨道│              │                           ┌────────────┐ │
│    │              │                           │浮动检查器  │ │
├────┴──────────────┴───────────────────────────┴────────────┤
│                    时间地层                                 │
└─────────────────────────────────────────────────────────────┘
```

不能像当前骨架一样无提示隐藏检查器。选中实体时检查器从右侧浮出，关闭后保留带实体类型的召回按钮。

### 4.3 紧凑桌面（960–1179px）

左坞也改为工具轨道触发的覆盖层；地图保持最少 620px 可用宽度。顶栏只显示数据集、时间摘要和命令入口，其余进入“更多”。

### 4.4 后续移动端

移动端不是把四栏压缩成一列，而是独立的 map-first 路由：地图为主，时间地层与检查器使用可切换底部 sheet。第一阶段只保证桌面和紧凑桌面，不提前牺牲桌面分析能力。

## 5. 任意时间切片体验

### 5.1 概念

一个“时间选择”是零个、一个或多个 `[start, end)` 区间的集合。用户可保存为命名选择，例如“春季周末”，但名称和日历周期不改变底层多区间模型。

### 5.2 创建

- 在时间地层空白处拖动：创建新选择；
- `Shift + 拖动`：向当前选择添加区间；
- `Alt + 拖动`：从当前选择减去时间；
- 双击事件：以访问或行程精确范围创建区间；
- 命令面板输入自然时间：“过去三个月的周末”“所有上海访问”，先预览再确认；
- 时间输入器支持精确 ISO/本地时间编辑，并明确显示时区。

### 5.3 编辑

- 拖动区间主体移动；拖动两端调整边界；
- 边界吸附到访问、行程、缺口和自然时间刻度，可按住修饰键临时关闭；
- 上下文操作：分割、合并、复制、平移、反选、与另一选择求交；
- 相交和相邻区间在提交时规范化合并，但编辑预览保留用户操作痕迹；
- 重叠区间只统计一次；区间之间不画实线连接。

### 5.4 表达

每个命名选择有稳定颜色，但底层真实性颜色优先：选择用半透明边框/遮罩，不能把未知缺口染成“确认”。顶栏摘要显示区间数和并集总时长。

## 6. 地图与时间线联动

| 动作 | 地图 | 时间地层 | 检查器 |
| --- | --- | --- | --- |
| Hover 事件 | 高亮路径/地点 | 保持 hover | 不切换持久内容 |
| Click 地图对象 | 保持相机或轻度聚焦 | 滚动并高亮范围 | 打开对应实体 |
| Click 时间事件 | 聚焦对应范围 | 持久选中 | 打开对应实体 |
| 刷选时间 | 实时低精度过滤 | 显示编辑预览 | 显示选择摘要 |
| 播放 | 跟随或保持相机 | 游标推进 | 显示当前事件 |
| 进入缺口 | 不沿虚线假移动 | 显示断层和时间跳跃 | 显示“未观测” |
| 切换处理版本 | 原子切换全部图层 | 原子切换全部事件 | 标注候选/已发布 |

Hover 状态和持久选择分开，避免鼠标经过时检查器抖动。

## 7. 图层系统

第一版核心图层：

- 确认轨迹；
- 推测连接；
- 访问与地点；
- 原始/可疑/排除点；
- 热力；
- 聚合/六边形；
- 地点边界；
- 交通方式；
- 质量覆盖。

图层行包含可见性、语义图标、名称、范围摘要和展开按钮。展开后才显示颜色、透明度、精度和过滤器。支持拖放排序，但底图和质量覆盖有明确的拓扑约束，不能拖到无意义层级。

## 8. 地图状态序列化

保存视图必须包含：

- 数据集和处理版本绑定方式；
- 规范化时间多区间；
- 相机、投影、底图和地图样式；
- 图层顺序、可见性、样式和过滤器；
- 颜色比例和聚合参数；
- 时间地层缩放、展开层和播放速度；
- 左右坞大小与折叠状态；
- 当前工作区和 UI 偏好。

持久选择实体不默认保存，除非用户明确选择“从此对象打开”。旧 schema 通过迁移器恢复，禁止让组件自行猜测。

## 9. 动效

- 初次进入：地图先可交互，左右坞在 220ms 内各移动 8px 落位；
- 选择实体：地图和时间地层同时出现 110ms 状态变化，检查器 220ms 打开；
- 多区间编辑：拖动时只更新 Canvas 和局部摘要，松手后 220ms 规范化；
- 缺口跳跃：游标在缺口前收束，未知时长标签出现，随后在下一个观测点淡入；
- 人工修正：被修正轨迹只执行一次 220ms 路径确认动画；
- 所有动画遵守 `prefers-reduced-motion`，播放帧不经 Motion/React 重渲染。

## 10. 键盘和命令面板

### 10.1 快捷键

- `⌘/Ctrl K`：命令面板；
- `1–5`：切换一级工作区；
- `T`：进入时间选择模式；
- `Shift + 拖动`：添加区间；
- `Alt + 拖动`：减去区间；
- `[` / `]`：上一个/下一个事件；
- `Space`：播放/暂停；
- `F`：聚焦当前对象；
- `I`：打开/关闭检查器；
- `⌘/Ctrl Z`、`⌘/Ctrl Shift Z`：撤销/重做时间编辑或人工修正；
- `?`：快捷键帮助。

时间手柄可聚焦，方向键按刻度移动，`Shift + 方向键` 使用更大步长。任何拖放功能必须有键盘等价操作。

### 10.2 命令分组

命令面板分为：导航、时间、地图、选择对象、处理版本和人工修正。结果按用户语言命名，例如“显示可疑点”，不显示内部 action 名。

## 11. 组件技术选择

- **Radix Primitives**：Dialog、Popover、Tooltip、DropdownMenu、ContextMenu、Tabs、Switch 等无样式可访问原语；不引入 shadcn 视觉层。
- **MapLibre**：底图、相机、基础矢量交互。
- **deck.gl**：大量点、热力、聚合、轨迹、GPU 过滤和二进制数据。
- **D3 scale/array/shape**：时间和空间比例尺、刻度与几何计算。
- **Canvas/WebGL 时间地层**：核心高密度时间 marks；不用一事件一 DOM。
- **Motion**：面板和语义状态过渡，不承担播放循环。
- **Zustand**：workspace、temporal、map、layers、selection、inspector、playback、jobs 八个逻辑 slice。
- **dnd-kit 或受约束自定义拖放**：图层和命名时间选择排序。
- **ECharts**：第一版不引入。未来只有独立的非核心统计图确有收益时再评估。

## 12. 性能策略

- Arrow/二进制列式数据替代大 GeoJSON；
- Web Worker 解码并 transfer buffers；
- 根据视口、时间多区间和像素误差请求多精度块；
- 低精度先显示，高精度渐进替换，语义锚点始终保留；
- 相机移动和刷选请求可取消、去重和合并；
- deck.gl 属性数组保持稳定引用，避免无意义 GPU 重传；
- 时间地层使用空间索引做命中测试；
- 拖动中不重新计算精确统计，只显示近似预览；松手后请求精确并集；
- React 组件按 store selector 订阅，播放游标放在 imperative rendering path。

## 13. 组件状态和可访问性

所有交互组件至少覆盖：默认、hover、focus-visible、pressed/selected、disabled、loading、error。

语义冗余编码：

- 确认：实线 + 颜色 + “已观测”；
- 可疑：点状描边 + 警示图标 + “可疑”；
- 未知：断层/空白 + 双边界 + “未观测”；
- 推测：虚线 + 低透明度 + “推测”；
- 排除：叉形点 + 红色 + “已排除”。

正文文字至少 WCAG AA；地图覆盖文字提供实色底；颜色比例和热力图提供色盲安全预设。

## 14. 首轮实现顺序

1. Design DNA 转为 CSS 变量和字体角色；
2. 建立 Zustand 共享状态与演示领域模型；
3. 重构工作区导航和可召回检查器；
4. 实现多区间时间选择数据结构与交互原型；
5. 让地图图层、时间地层和检查器共享选择；
6. 加入缺口、推测连接、开放行程和置信度演示；
7. 接入真实 processor/API；
8. 加入 deck.gl 二进制渲染和高密度 Canvas 时间地层；
9. 完成保存/恢复地图状态和候选处理版本预览；
10. 做宽桌面、普通桌面和紧凑桌面截图回归。
