# RouteFrom 前端现状审计

日期：2026-08-05。对象：提交 `ece4e67` 的 `app/` 页面。性质：只读运行与截图审计，
不代表视觉方向已获用户确认。

## 1. 取证范围

- 运行 Next.js 16.3 开发服务器并访问 `/`；
- 检查 1440×900、1180×760、960×700 三个桌面视口；
- 读取可见 DOM、浏览器控制台和关键布局尺寸；
- 点击热力图层与一级工具轨道，核对状态和内容是否一致；
- 对照 `docs/FOOTPRINT_PROCESSING_ALGORITHM.md`、
  `docs/FRONTEND_EXPERIENCE_ARCHITECTURE.md` 和当前 Design DNA 草案。

## 2. 当前优势

- 地图占据主要视觉面积，左右坞和底部时间轴的基本空间关系正确；
- 深色外壳克制，地图与个人长期足迹的沉浸感方向成立；
- 图层、命名时间选择、检查器和时间轴已出现为产品概念，不是普通管理表格；
- 1440px 下主要区域没有溢出，1180px 和 960px 下地图仍保留 880px/660px；
- 页面运行时没有捕获到浏览器 warning/error；
- MapLibre 画布和地点 marker 已正常初始化。

## 3. 阻断真实产品体验的问题

### P0 — 地图没有显示轨迹

三个视口截图中只看见地点 marker，没有看见代码声明的薄荷色 route 或 context line。
当前页面因此没有完成核心工作：“从空间上看见足迹”。在接真实 API 前必须先确定是
MapLibre source/layer 生命周期、样式层级还是截图渲染问题，并建立可重复视觉测试。

### P0 — 全部业务内容是静态演示

- `WorkspaceShell` 直接写死数据集、日期、距离、地点和活动；
- `MapCanvas` 使用固定上海线段和地点；
- `Timeline` 使用百分比定位的静态 `<i>` 元素；
- 已完成的 `/api/workspace/query` 没有被页面调用；
- 没有 Zustand 共享领域状态。

这意味着当前地图、时间轴、检查器和图层并不共享真实实体或处理版本。

### P0 — 时间切片只是按钮，不是区间集合编辑器

页面能展示“4 个不连续区间”文案，但不能创建、移动、缩放、分割、减去、合并或播放
多区间；时间轴仍是固定日刻度，尚未体现算法的日历无关 `[start, end)` 模型。

### P1 — 响应式行为丢失上下文

- 1440px：左右坞均显示，布局完整；
- 1180px：检查器直接 `display:none`，没有召回按钮，选中实体信息消失；
- 960px：左坞仍固定 248px，没有按架构要求成为 overlay；日期控件被压成两行；
- 低于 960px 依靠 `min-width`，没有未来 map-first 降级路径。

### P1 — 导航状态与内容不一致

点击工具轨道“数据”后，active rail 会变为“数据”，左坞标题仍为“足迹图层”。当前
工具轨道只改变颜色，不切换工作上下文。导航命名也仍按技术对象，而不是探索、时间线、
地点、质量审阅和处理版本等用户任务。

### P1 — 图层状态文案不一致

点击“足迹热力”后第三个图层获得 `is-visible`，图标变为可见，但副标题仍为“未显示”。
图层数组中的 `visible` 字段也没有被使用，存在两套状态来源。

### P1 — 可访问性基线不足

- 28 个按钮中有 5 个没有可访问名称；
- 应用 CSS 没有 `:focus-visible`，仅 MapLibre 内置控件有焦点样式；
- icon-only 按钮的含义不完整；
- 没有 skip/landmark 策略、可调整手柄或拖放键盘等价操作；
- 没有 `prefers-reduced-motion` 降级。

### P2 — 视觉系统尚未形成 RouteFrom 独有签名

骨架接近“深色 SaaS + 薄荷色 + 四栏仪表盘”常见解法。当前底部时间轴只是装饰横条，
没有表达未知断层、推测虚线、质量状态、交通方式和多时间取样窗，因此 Design DNA 草案
提出的“时间地层”签名尚不存在。

### P2 — 字体与令牌实现漂移

依赖已经包含 IBM Plex 字体，但 `globals.css` 仍使用 Segoe UI/雅黑；现有 CSS 变量也与
Design DNA 草案的语义命名、字体角色、动效尺度和领域颜色不一致。

## 4. Design DNA 判断

当前 `app/design/routefrom.design-dna.json` 完整覆盖 Design DNA 的三维 schema，且与产品
语义相符，但它是目标方向草案，不是从外部参考中获得用户确认的最终规范。

可保留的部分：

- “夜间个人时空观测台”而非后台看板的产品隐喻；
- 确认、停留、未知、推测和排除的领域颜色；
- 地图安静、时间地层成为唯一视觉签名；
- 视觉性能用于真实数据密度而非装饰粒子；
- Canvas/WebGL 时间地层与 deck.gl 地图的技术分工。

需要用户参考图或后续实现截图继续校准的部分：具体色值、字体组合、面板密度、圆角、
玻璃程度、地图底图风格和动效强度。

## 5. 下一实现门槛

在大规模视觉重构前，下一阶段必须先建立：

1. 一个唯一的 Zustand 领域 store；
2. API client、加载/错误/取消/版本一致性；
3. 真实或版本化 fixture 驱动的地图轨迹；
4. `TimeSelection` 集合运算和序列化；
5. selection/hover 在地图、时间和检查器间的共享契约；
6. 响应式检查器召回与基础 focus/reduced-motion 状态。

完成这些后，再使用 frontend-design 技能按确认后的 Design DNA 实现高完成度视觉，避免
在静态假数据骨架上反复打磨不可复用的表面。
