# 完整备份与恢复：实现边界及执行顺序

更新时间：2026-10-17。完整备份/恢复仍是网站 PRD 的未完成项；归档底层及后台备份、确认恢复计划、追加恢复和重算发布已实现，网站上传、下载与确认界面尚待接入。后台验收不等同于网站恢复功能完成。

## 归档 v1：已实现

文件为 `*.rfbackup.zip`，仅接受一个 `manifest.json` 和清单列出的 `raw/<原数据集 UUID>.csv`。ZIP 内路径由固定规则生成，绝不使用原文件名解压落盘。

清单严格限定：

- `format=routefrom-library-backup`、整数版本 `1`、原观测指纹版本、备份时间。
- 足迹库名称、时区、库输入版本；来源设备的原 ID、key、名称、解析器及建立时间。来源 ID 只是归档中的引用，不是目标账号授权。
- 全部原始上传文件的名称、大小、SHA-256、来源、参与状态、上传/加入/撤销时间。包含 active、withdrawn 及尚未入库的 unprocessed 原件；后者可包括失败或排队中的原件，不将其当成可靠观测。
- 文件分别保存 `datasetStatus` 和最新导入任务的 `jobStatus`。现有实现中失败任务的原数据集可能仍标 pending，成功的原件也可能标 processing，不能用其中一列代替另一列。
- 当前已发布快照的保留冲突选择，以及当前未完成任务已有的显式选择，按后台任务实际合并顺序保留；每个选择携带时间戳、源 ID 和精确指纹。
- 地点人工备注、旧修订号、建立/更新时间、位置和最多 12 个原始观测锚点；没有当前关联的旧备注也保留。
- 最近地图配置及其修订/更新时间、全部命名视图及建立时间。仅接受当前地图 v1 完整配置，不接受任意 Zustand 状态或旧页面 ownerId。

不包括密码、会话、数据库连接串、私有目录、原用户认证主体、可执行 SQL 或派生地图缓存。原始 CSV 原样保留，轨迹/停留等派生结果恢复后重新计算；旧后台运行 UUID 和 CAS 修订号不能当成目标账号可直接使用的身份。归档包含私密足迹且**没有加密**，未来下载界面必须提示安全保存。

数据库导出使用一条账号/个人库范围的 SQL，从同一个 MVCC 快照读取所有元数据、备注、配置和当前选择；归档写入期间不持有库行锁。所有原件都要存在且哈希吻合，不能丢一份后仍声称备份成功。暂不支持的原件存储后端明确拒绝，不能静默遗漏。

## 校验与资源边界：已实现

- 原件每份最多 80 MiB，原件总量最多 1 GiB，256 份文件、128 个来源；ZIP 另留清单和容器开销。
- 清单最多 32 MiB；1000 条备注、100 个命名视图、100000 个不同证据引用、5000000 个原始行的扫描上限。超限报错，不截断或丢弃。
- 在 ZIP 库构造成员对象之前检查尾目录大小和数量，拒绝多卷、ZIP64、注释、扩展字段、加密、特殊文件、未知路径、重复成员和未声明成员。读取时按块计算 SHA-256，核对声明与实际长度；ZIP CRC/压缩异常也会拒绝。
- 原件不解压到任意路径；已注册 CSV 使用与正常文件导入相同的流式解析器。失败/未处理原件只保存原字节，不读取其内容作为决策或备注证据。
- 备注/选择必须能从所含 CSV 按原 source UUID 和完整指纹重建；选择时间也须一致。附近坐标、舍入坐标、文件行号不替代观测身份。
- 清单拒绝重复 JSON key、非有限数、未知字段、非法类型及不支持的配置。网站与 Python 共用地图 v1 接受/拒绝样例，避免配置导入器悄悄丢字段。
- 创建归档使用独占新文件，现存备份不覆盖。失败只清理本次新建的不完整输出，不移除原始文件。读取结束再次核对归档摘要，拒绝校验中发生变化的文件。
- 私有 CSV 路径检查下沉为 worker 与备份共享模块：允许根目录挂载，不允许根目录以下的链接/junction 指向别的资产，包括仍位于同一私有根目录中的资产。

## 恢复证据准备：已实现

`remap_backup_evidence` 要求完整、一对一的目标来源映射。它以已核验的原始字段在目标来源 UUID 下重新计算指纹，同步重映射冲突选择和备注锚点。不把源账号的备注 UUID 作为可直接插入的目标主键，而标为 `originId`，供后续幂等和冲突识别使用。无来源或存在歧义时拒绝，不用最近位置补救。

这个纯函数本身不是账号鉴权，也不写数据库。实际后台恢复另行解析**目标账号自己的**来源、数据集及观察 ID；不能信任上传文件指定目标用户或主键。

## 后台任务和实际恢复：已实现

- `0020_library_archive_jobs.sql` 增加账号/个人库范围的任务、按尝试令牌隔离的准备批次与恢复回执。复用独立 Python worker，不在上传请求中重算。
- 首次执行只核验归档并生成待确认计划。确认绑定目标库状态摘要；准备时不占库写锁，提交时锁库、复核状态及真实时钟租约。其他窗口改变文件、备注或视图后必须重新确认，不能沿用旧计划。
- 普通处理和归档任务共同锁定个人库，锁后另用新语句重查对方队列，防止两个表在旧 MVCC 快照下同时领取；过期令牌不能提交。
- 新原件先独占写入私有暂存并核对完整摘要，以同一 CSV 解析器建立不可变输入，再按批准备精确观测。最终事务追加来源、成员、全部来源行、备注锚点与配置；失败回滚库成员及人工记录，保留旧地图。
- 重复原件按目标账号 SHA-256 去重，已有来源和参与状态保留；新成员恢复 active/withdrawn，失败/未处理原件只留存并显示为需要检查后重试的导入任务，不自动参加计算。
- 新备注使用新 UUID；回执记录原对象及内容摘要。相同备份再次恢复不重复添加，也不复活之后被用户删除或覆盖之后改名的备注/视图；归档内容发生变化时新增保留，不覆盖当前人工记录。来源映射有歧义时拒绝，不猜测。
- 空白默认库可恢复库名、时区与最近视图；非空库保留当前设置，将备份最近视图另存为命名视图。备注和视图上限按合并后总量校验，超限回滚，不截断。
- 新增普通重算任务，当前已发布冲突选择优先于备份选择。归档状态保持 processing，只有正常处理器成功发布后才标 succeeded；失败或待决仍保留旧地图。元数据合并成功但重算失败不宣称完整恢复完成。
- 暂存与新输出仅清理本尝试独占创建的资产；数据库引用不明时保留原件。普通上传遇到已有暂存/生成数据集时，将用户本次提供且摘要相同的字节提升为永久原件，避免复用内部路径导致无法下载。

## 当前可用的运维命令

在 `processor` 目录，以项目虚拟环境运行。导出只供持有数据库运维权限的调用方使用；不提供绕过网站鉴权的公开接口。

```powershell
../.venv/Scripts/python.exe -m routefrom_pipeline.backup export --user-id <用户UUID> --library-id <个人库UUID> --data-dir <私有目录> --output <新文件.rfbackup.zip>
../.venv/Scripts/python.exe -m routefrom_pipeline.backup verify <新文件.rfbackup.zip>
```

导出读取现有 `DATABASE_URL_DIRECT`；连接串只放环境文件，不写进命令历史。验证不需要数据库，输出只有验证状态、数量和归档摘要，不显示坐标、备注内容或私有路径。命令中不提供直接 `restore`：实际恢复由账号范围的持久任务和计划确认驱动，而不是开放一个绕过确认的运维写入口。

逐阶段测试证据见 [WEB_DATA_LIBRARY.md](WEB_DATA_LIBRARY.md)。`0020` 先在隔离测试库验证，再执行到项目库；未导入或改写项目库的用户足迹，未部署公网或上传用户原始 CSV。
