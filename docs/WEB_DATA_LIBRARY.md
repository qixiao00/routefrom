更新时间：2026-10-10。用户已确认部署成网站，并授权实现 CSV 导入、导出和多文件管理。

## 已确认的目标

- 延续 Next.js / React / MapLibre 网站，正式存储采用 PostgreSQL/PostGIS。
- 第一版每个账号一个个人足迹库，多次上传 CSV 合并到同一时间序列。
- 文件和导入批次独立留存；重复文件和重复观测不增加足迹计数。
- 精确去重不做空间舍入，不删除不同时间的重复经过。
- 同时刻不同观测保留证据；处理结果不能依赖上传顺序。
- 任意时间范围和多个不连续区间继续支持，并按地图视野加载。
- 新版本处理成功后原子发布；失败保留上一版可查看数据。
- 地点备注和地图配置存入账号资料，导出支持 CSV 和完整备份。

## 数据处理边界

一个 `source_id` 表示同一记录设备/来源。上传文件名、上传时间和 CSV 行号不参与观测身份。
所有原始字段参与精确指纹；同坐标同时间但精度等字段不同会保留为不同候选。
当前核心将所有同时间多候选（含多设备）报告为冲突，调用者必须提供合法候选决策才能获得算法输入。
网站每次展示最多 200 组待决冲突，允许逐批提交；处理器会重新检查全库，直到所有当前冲突都已解决才发布。
后续增加基于证据的自动选择，并记录选择版本；不能用“最后上传覆盖”代替冲突处理。
`content_sha256` 描述完整观测集合；处理任务还必须把冲突决策和算法参数纳入输入版本，不能仅用此摘要复用运行。

先完成正确的全库重算和版本发布，再优化受影响片段的增量计算。涉及常去地点等全局结果时必须重新聚合。
