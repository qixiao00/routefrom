# RouteFrom 产品需求与执行台账

状态：持续维护。最后更新：2026-08-05。

本文件是 RouteFrom 的产品范围、技术阶段和验收证据总入口。算法定义以
`docs/FOOTPRINT_PROCESSING_ALGORITHM.md` 为准，前端交互定义以
`docs/FRONTEND_EXPERIENCE_ARCHITECTURE.md` 为准，数据库结构以迁移文件为准。
当三者冲突时，先保持数据真实性和可解释性，再调整产品交互与实现。

## 1. 产品目标

RouteFrom 是一个私人的时空观测与回忆工作台。用户导入长期足迹后，应能：

1. 看见真实观测、可疑观测、未知时间和推测连接之间的区别；
2. 理解并修正停留、访问、地点、行程和交通方式；
3. 创建、组合、编辑和保存任意多个连续或不连续时间区间；
4. 在地图、时间地层和检查器之间保持同一选择与同一处理版本；
5. 保存并恢复完整地图与工作区配置；
6. 在十万到百万级点位下保持渐进、可交互的视觉体验；
7. 保留源数据、算法版本、解释证据和人工修正，不静默覆盖历史事实。

## 2. 不可违反的产品原则

- 原始观测不可修改；清洗、地图匹配和人工修正均产生新版本。
- 手机未带、关机或未采样形成未知时间，不自动解释为移动或停留。
- 实线只表示确认轨迹；缺口和开放边界的猜测必须使用虚线且不计入确认统计。
- 时间选择是任意 `[start, end)` 区间集合，不固定为全局、月度或单日。
- 不连续时间区间之间绝不画实线，重叠区间统计只计算一次。
- 地图、时间线和检查器必须引用相同 `processingRunId` 和逻辑实体。
- 自动识别输出概率、选择层级和解释贡献；证据不足时允许返回 `unknown` 或父级方式。
- 用户修正默认只用于个人模型，不做未经同意的跨用户训练。
- 前端不伪造精确值，不用视觉效果掩盖数据未知性。

## 4. 已确认的关键决策

- 灵敢足迹可能根据运动状态调整采样，不能假定全局固定采样间隔。
- 长数据断点通常按没带手机、手机关机或系统未采样理解，底层状态是“未知”。
- 缺口保留，并可按置信度显示虚线猜测；猜测不进入确认距离和时长。
- 道路、轨道、水域、站点和 POI 可作为独立地图证据层，不覆盖 GPS 事实。
- 高置信度可使用地图匹配路线，低置信度自动回退平滑或清洗 GPS。
- 第一版采用可解释概率模型，后续用人工修正数据升级个人机器学习模型。
- 产品支持任意时间范围和多个不连续时间切片，不使用固定全局/月度/单日模型。
- 前端采用 MapLibre + deck.gl；D3/visx 负责尺度与定制可视化；ECharts 第一版不引入。
- Design DNA 先于视觉实现；当前 DNA 和体验架构仍是待用户确认的探索草案。

## 5. 发布阶段

### R0.1 — 可解释算法基座（当前）

目标：从真实 CSV 得到可审计的质量、连续性、停留、行程、方式和多精度轨迹。

完成条件：

- 固定回归覆盖异常跳点、长缺口、交通暂停、开放行程和不连续时间区间；
- 所有输出携带处理版本、置信度和解释；
- 数据模型和写入事务不会混合不同数据集或运行；
- 每个大阶段有独立 Git 提交并推送。

### R0.2 — 可运行数据系统

目标：完成从上传 CSV 到激活候选运行的真实 PostGIS 全链路。

范围：

1. 数据集、导入批次和不可变点的数据库写入；
2. worker 编排、阶段进度、幂等重试和失败恢复；
3. 地点解析 v1；
4. ENU Kalman/RTS 平滑；
5. 可插拔地图证据与 HMM 地图匹配 v1；
6. 时间线、检查器和选择摘要查询；
7. 真实 PostGIS 集成测试及 10 万点批量性能。

### R0.3 — 算法驱动的个人工作台

目标：用户能在一个真实数据工作区中探索、组合时间、理解算法和修正结果。

范围：

1. Zustand 领域 store 与请求生命周期；
2. 算法语义驱动的一级导航；
3. 可调整左右坞和时间地层；
4. 任意多区间创建、移动、缩放、分割、减法、并/交/差和撤销；
5. 地图—时间线—检查器共享 hover/selection；
6. 观测、未知、推测和排除的冗余视觉编码；
7. 人工修正、字段锁和候选版本差异审查；
8. 键盘、命令面板、减少动效和桌面断点验收。

### R0.4 — 高密度可视化与完整视图保存

目标：大量点位下仍可平滑探索，并可复现完整地图状态。

范围：deck.gl 二进制轨迹、点、热力和聚合层；Canvas/WebGL 时间地层；Web Worker
解码；渐进 LOD；请求取消和缓存；地图视图 schema 迁移；真实设备 FPS 和首屏测量。

## 8. 完成定义

“项目完成”不能只由单元测试或页面看起来完整证明。至少需要：

- 真实灵敢 CSV 从导入到激活运行全链路成功；
- 真实 PostgreSQL/PostGIS 执行全部迁移、约束和回滚测试；
- 固定算法验收样例全部通过并能在 UI 中解释；
- 任意多个不连续时间区间在地图、时间地层和统计中一致；
- 用户能查看并修正访问、地点、行程和交通方式；
- 视图保存/恢复包含地图、图层、时间和面板状态；
- 10 万点当前数据集和更大合成集有记录的服务端、主线程、GPU 和内存指标；
- 宽桌面、普通桌面和紧凑桌面完成截图回归、键盘和减少动效验收；
- 所有未确认推测均保持虚线和统计隔离。
